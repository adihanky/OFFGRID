# Demo custody writer

The [custody service](../apps/api/src/modules/custody/custody.service.ts) is integrated into issuance and transfer settlement for newly created simulated assets. Both v1 and v2 transfers use the writer when `custodyEnabled: true`. Existing assets retain their legacy behavior until an explicit migration reconstructs provenance and enables custody; deployment alone does not backfill them.

The target integration contract is the [overhaul LLD](WALLET_ASSET_OVERHAUL_LLD.md). The writer accepts a caller-owned MongoDB transaction session. Issuance creates a root lot. Transfers consume deterministic FIFO inputs, create a recipient lot and optional change lot, and record exact allocations. Lot limits reject the full operation rather than reduce the payment. Quantities use BSON Long and bigint.

Lots, events, edges and per-asset hash heads share that transaction. Event hashes commit inputs, outputs, allocation amounts, domain references and predecessor hashes. Original lot quantities remain immutable; spending records a consuming event. The service has no public route, direct balance editor, production seed job or arbitrary user impersonation operation.

The verifier checks event hash continuity, canonical payloads, graph conservation, input/output allocations, reference quantities, owners, participants and missing events/heads. Coverage includes roots, splits, merges, multihop ancestry, minimum units, input limits, tamper detection and rollback. Transfer failure-injection assertions include the custody boundary and check no partial balance/journal/chain/outbox/lot effects. [Explicit migration](WALLETS.md) reconstructs legacy lineage under a labeled policy. Hash chains require a trusted checkpoint for administrator-resistant evidence.

Authenticated `GET /api/v2/custody?cursor=<event-id>` returns at most 20 own-wallet events and a next cursor. `GET /api/v2/custody/:id` returns one participant-authorized event or 404. The [query service](../apps/api/src/modules/wallets/custody-query.service.ts) returns quantities, reference/hash metadata, input/output lot IDs and allocations for that event, with counterparties labeled generically. It never exposes canonical payloads, other users' wallet IDs, emails or a path to unrelated earlier events. The browser displays issuance, sends, receipts, splits/change and reconstructed provenance in expandable activity rows. This is participant-scoped event detail, not unrestricted recursive graph browsing.

The [functional fixture](../tests/support/custody-harness.mts) invokes real issuance and transfer services in disposable replica-set databases. An explicit-abort scenario additionally checks the writer's caller-owned transaction contract.
