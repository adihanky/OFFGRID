# Wallet and Transfer QA plan

Scenario map for the implemented Wallet and Transfer slice. The primary agent owns integration, review and verification; no independent review is claimed for this session. Scope follows [the implementation handoff](WALLET_AND_TRANSFER_IMPLEMENTATION.md) and [LLD](WALLET_AND_TRANSFER_LLD.md). Reported execution evidence and limits are recorded below and in [onboarding.md](../onboarding.md).

## Fixtures and execution boundaries

Every HTTP/persistence scenario creates `p2p_transfer_test_<32 lowercase hex>` on local MongoDB replica set `rs0`, runs the real Nest application, and removes only its validated generated database name in cleanup. Distinct cookie jars represent Alice, Bob, Carol, and anonymous callers. Synthetic password identities and controlled signed OAuth fixtures never contact external providers. Issuance uses the implemented balanced fixture service; intentional corruption is restricted to these disposable databases. Quantity boundary tests use precision 0, 2, and 8 asset fixtures with BSON Long values. Tests must never write production or the application database.

Failure injection acts at explicit execution boundaries with deterministic barriers rather than timing sleeps. Each aborted settlement must leave original balances and no transfer journal, chain entry, or outbox event. A committed-response-loss case must prove the opposite: one complete persisted effect, recovered under the original identity. Driver/network ambiguity and real process termination require separate evidence; an application hook alone is not a network fault experiment.

The primary agent serializes test commands because reports share `.local/test-results/`. `scripts/npm.ps1 run check` includes lint, types, both suites, builds and formatting. Inspect both JUnit XML reports and Cucumber HTML and record actual counts and failures/skips. Transfer admission and replay branching also have focused coverage in `tests/unit/transfer-admission.test.mts`; client response-body interruption is covered in the client unit and functional files. Full-app fixture setup permits 60 seconds for all domain schemas/indexes; unit files execute sequentially to bound startup resource use.

## Scope and evidence limits

Full transfer history, chain explorer UI, socket delivery, real funds, production issuance, production deployment, load-envelope proof and external audit checkpoints are out of scope. C01 exercises helpers; C05 separately renders the actual React/StrictMode app in installed Chrome with synthetic intercepted API responses. It verifies keyboard input, unavailable-wallet messages, review/edit/confirm, wallet refresh and new-transfer input. Browser pending polling/reload and cross-tab account changes remain unverified. T12 exercises recipient suspension before identity fencing; it does not exhaustively test account/asset suspension races. R07 loses a real driver's commit acknowledgement through a wrapper after server commit, rather than dropping an actual network connection. Restart recovery closes and reopens the application in one process; operating-system process termination and replica-set failover remain untested. See [test prerequisites](../tests/README.md) for browser selection and focused commands.
