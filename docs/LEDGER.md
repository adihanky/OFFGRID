# Ledger architecture

`apps/api/src/modules/ledger/ledger.service.ts` owns append-only double-entry journals and read-only reconciliation. LedgerModule exports LedgerService to Accounts and Transfers. It uses DatabaseService and never starts a transaction for a journal write: `pair(JournalPair, ClientSession)` requires the caller's session so all business effects commit together. JournalPair uses typed referenceKind `transfer` or `demoIssuance`, ObjectId references and account IDs, exact positive bigint quantity, asset and UTC timestamp. A pair must use distinct accounts and identical positive bounded quantity; the writer inserts one debit then one credit sequentially.

The `ledgerEntries` validator requires ObjectIds, enum side/reference kind, positive BSON Long quantity and Date. Unique `journal_reference_side` covers `(referenceKind,referenceId,side)`; account/history index covers accountId/time/ID. Entries have no TTL, update endpoint or repair command. Concurrent duplicate writes fail the parent transaction. No transport or external side effects occur inside callbacks.

`reconcile()` runs one snapshot transaction, sums credits minus debits for every ordinary/system account, verifies same-asset balanced pairs, checks account references and exact correspondence to committed transfers or issuance records, and checks missing journals. It returns `{ok,issues}` without changing any financial data. System issuance debit participates in balance reconciliation but is not an ordinary user transfer or chain entry. Future corrections require an explicit compensating journal workflow, not edits.
