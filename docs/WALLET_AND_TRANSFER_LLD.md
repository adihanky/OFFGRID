## Public and domain types

IDs are lowercase 24-hex ObjectIds. API quantities are bounded strings (maximum 30 characters), grammar `^(0|[1-9][0-9]*)(\\.[0-9]+)?$`; precision is an integer 0..8. Quantity is positive and at most 9223372036854775807 base units. No signs, exponent, whitespace, JSON numbers, or excess fractional places. Fixed precision formatting uses bigint division; `1`, `1.0`, `1.00` at precision 2 share request identity `100`. `0.01` is one unit; precision-8 `0.00000001` is one unit; precision-0 `1.0` is invalid. User balances range 0..INT64_MAX; the non-login issuance account alone may range INT64_MIN..0. BSON Long is read without numeric promotion and converted through decimal strings to bigint.

Shared contracts: `PublicPeer {id,publicHandle,displayName}`, `WalletResponse {accounts:[{assetId,code,displayName,precision,balance,status}]}`, `PeerResponse {peer}`, `CreateTransferRequest {recipientId,assetId,quantity}`, `TransferResponse {transfer:{id,sender,recipient,asset:{id,code,displayName,precision},quantity,status,rejectionCode,createdAt,updatedAt}}`. Identity and asset display projections are snapshotted at admission; immutable IDs, precision and units determine intent. No email, keys, leases, hashes or system balances are exposed. Status is PENDING/COMMITTED/REJECTED. Rejection codes cover insufficient balance, unavailable participants/accounts/assets and recipient balance overflow.

All four routes require AuthGuard, no-store headers and strict query/body validation. POST additionally requires existing session-bound CSRF and origin checks. Unsupported assets/self-transfer/malformed inputs return 400 before registration. UUID keys normalize lowercase. Sender/key uniqueness is durable; canonical identity is JSON array `[1,senderId,recipientId,assetId,units]`, SHA-256 UTF-8. Replays resolve the stored asset precision before mutable eligibility and compare hash. Different content returns 409. POST returns 201 new commit, 200 committed replay, 202 pending, 422 persisted rejection; status reads return 200. Recipients see committed records only; strangers and unknown IDs receive identical 404. Registration failures return sanitized 503, requiring same-key retry. Rate limits are persisted per caller/action/minute: submit 60, peer 120, reads 240.

## Persistence and initialization

Use official driver 7.7.0, existing DatabaseService, ObjectIds, UTC Date and Long fields. Each boundary creates strict BSON validators and named unique indexes before HTTP startup. Existing incompatible documents or duplicate indexes fail startup; no destructive migration. Existing users accept optional Long `transferEligibilityRevision` with absent-as-zero increment semantics. Collections, fields and indexes follow the module HLD, implemented explicitly in module stores. Terminal records and journal/chain identities have no TTL. Only throttle buckets expire.

Catalogue starts empty. Explicit demo command creates DEMO precision 2 and synthetic identities, then issues 1000.00 per fixture. No startup balances or public issuance. `AccountsService.createAsset({code,displayName,precision})` creates immutable catalogue/head atomically and rejects conflicting catalogue definitions. `issueDemo({fixtureKey,userId,assetId,quantityUnits})` writes system debit/user credit, issuance identity and typed ledger pair atomically; identical reruns do nothing and conflicts reject. Caller CLI enforces development/loopback/database allowlists before connecting. A URI database path is accepted only when it exactly matches the explicit allowlisted `MONGODB_DB`, including the default quick-start URI; empty paths remain valid. Internal tests use disposable databases.

## Transactions and dependency graph

Auth exports a narrow IdentityEligibility service. Accounts imports Auth and Ledger; Transfers imports Accounts, Auth, Ledger, Chain and Outbox. Recovery belongs to TransfersModule to avoid a circular module dependency. All mutations require ClientSession; no Promise.all inside a transaction. `withTransaction` in pinned sessions.ts accepts timeoutMS for the complete callback/commit retry budget: 10 seconds, majority write concern, snapshot read concern, primary preference. Lease is 30 seconds. Reads/writes within the session inherit its timeout. Claims and admission use majority acknowledgements.

Execution claims PENDING with expired/null lease and due time, sets random attempt UUID, increments attempts, then writes that token-matched transfer inside the transaction. In sorted participant-ID order, Auth performs real conditional active-user revision increments; Accounts provisions zero user accounts, checks active status and applies bounded debit and credit. Ledger inserts a typed equal pair. Chain reads the active catalogue and enabled head and advances its sequence/hash conditionally in the same session. Finally status COMMITTED and stable outbox event are written. The transfer write fence makes takeover conflict with any earlier transaction. Suspension must update the same user/account document; asset status changes update catalogue/head in one transaction through Accounts.

Only a domain exception thrown before commit, followed by driver abort, may produce fenced REJECTED. Other errors (including commit uncertainty) leave PENDING and schedule backoff; read authoritative state to reconcile. A post-commit response-loss boundary cannot create a rejection. Old attempt tokens cannot commit or reject after takeover. Recovery calls exactly the same executor, bounded batch 20, interval 2 seconds, exponential backoff capped 60 seconds with jitter. Startup starts recovery only after module initialization; shutdown clears timer and waits in-flight work. No maximum retry count converts outages to business rejection. Session revocation after admission does not cancel a request.

## Journal, chain and integrity

Ledger references are `transfer` or `demoIssuance`; unique reference/side enforces one pair. Pair validation requires distinct account IDs, same asset and positive equal quantities. Reconciliation computes signed journal totals and verifies pair correspondence with committed transfers/issuances and every account balance, without repairs.

Chain genesis is 64 zero hex characters and sequence zero. Canonical version 1 is UTF-8 JSON array `[1,sequenceString,transferId,senderAccountId,recipientAccountId,assetId,unitsString,committedAtISOString,previousHash]`. SHA-256 lowercase hex; sequence is positive signed Long and checked before increment. Stored canonical bytes are rehashed; verification checks sequence, predecessors, head, committed transfer fields, journal accounts/amounts and missing/extra artifacts. One head per asset intentionally serializes appends. External checkpoints and privileged rewrite resistance remain future work.

Outbox event ID is `transfer:<id>:committed`; event `transfer.updated`, schemaVersion 1, minimal participant/status/time payload. Persist with deliveredAt null; there is no transport and nothing marks events delivered. Recovery is implemented here; socket delivery/history/chain screens remain separate modules.

## Client and verification

Lift authenticated identity into shared App state; retain auth regressions. Wallet lists fixed precision balances; exact handle lookup precedes review with recipient/asset/quantity. A confirmed intent owns one UUID and canonical request persisted in sessionStorage scoped to user ID. Retry after timeout, interrupted response body or reload reuses it; pending lookup polls boundedly, with explicit unresolved messaging and manual retry. Terminal result permits a new intent; sign-out/account switch clears private state. 401 clears session UI, including when its response body cannot be decoded. Client validation is advisory, server authoritative. React text rendering provides escaping; forms use labels, alert/status regions and keyboard controls.

Recipient and quantity remain editable while balances load or the catalogue is empty, unavailable or disabled. Explicit status text explains missing assets and balance-load failures. Asset selection and review require a successfully loaded active asset; a zero balance alone does not disable review. Refresh preserves typed details and an active selection, replacing a removed or disabled selection with the next active asset. A failed refresh blocks review until balances load successfully. Only in-flight peer lookup/submission disables the editable fields.

Unit and Cucumber suites cover happy, negative, edge, authorization, concurrency, rollback, takeover, response loss and reconciliation per QA map. Deterministic clock (`TransfersService.now`) and stage hook (`fault(stage)`) allow isolated injected boundaries: debit, credit, ledger, chain, status, outbox, afterCommit. Public internal `claim`, `execute`, `recover` methods permit worker/fencing verification. Real database suites prove transaction effects; actual network failover/process kill and browser rendering need distinct evidence and must not be inferred from injected hooks. Full check and XML counts are recorded by QA after integration.
